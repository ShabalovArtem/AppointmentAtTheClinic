Гістограма запізнень пацієнтів (Д2.5)

Ray і відновлення. Обробка запитів переходить у задачі Ray; слот займає приймач ефекту, ключ ефекту — request_id. Повтор задачі після відмови не займає слот удруге.

Режим задає сервер: EXECUTION=ray (задачі Ray, межа IN_FLIGHT_LIMIT) або local (пул ЛР1). Запити подаються на вкладці ЛР1.

Керована відмова after_effect_before_ack

Виконавець падає після запису ефекту, але до підтвердження задачі.

docker compose exec api touch /faults/after_effect_before_ack
# подати запит на вкладці ЛР1 — задача впаде після запису ефекту, Ray її повторить
docker compose logs api | findstr "effect.duplicate ray.task_done"
# або дослід цілком:
python DPC/experiments/lab3/fault.py
